# Stage 4: Generate Description

## Task

Generate comprehensive documentation for the HLS design at `{{DESIGN_DIR}}`.

## Instructions

1. **Read all source files** in `{{DESIGN_DIR}}`:
   - Kernel implementation (`.cpp`)
   - Header files (`.h`, `.hpp`)
   - Understand the algorithm, interface, and purpose

2. **Analyze the design**:
   - What does this kernel compute/process?
   - What are the inputs and outputs?
   - What algorithm or technique does it use?
   - Are there any HLS-specific optimizations (pragmas)?

3. **Create `description.md`** following this template:

```markdown
# {{DESIGN_NAME}}

## Overview

[1-2 paragraph description of what this HLS kernel does. Explain its purpose and typical use case.]

## Interface

### Top Function
- **Name**: `{{TOP_FUNCTION}}`
- **Return Type**: `{{RETURN_TYPE}}`

### Parameters

| Name | Type | Direction | Description |
|------|------|-----------|-------------|
| param1 | type | in/out/inout | Description |
| ... | ... | ... | ... |

## Algorithm

[Describe the algorithm or computation performed. Include:
- High-level steps
- Any mathematical operations
- Data flow description]

## Implementation Details

### HLS Pragmas
[List and explain any HLS pragmas used, e.g.:]
- `#pragma HLS PIPELINE II=1` - Enables pipelining with initiation interval of 1
- `#pragma HLS ARRAY_PARTITION` - Partitions arrays for parallel access

### Data Types
[Note any special data types used:]
- Fixed-point types (ap_fixed, ap_int)
- Custom structs
- Stream types (hls::stream)

## Dependencies

### Source Files
- `{{kernel}}.cpp` - Main kernel implementation
- `{{kernel}}.h` - Header with declarations
- [List other files]

### External Dependencies
[List any external libraries or headers required]

## Usage Example

```cpp
// Example of how to call this kernel
#include "{{kernel}}.h"

int main() {
    // Declare inputs/outputs
    // Call kernel
    // Process results
}
```

## Notes

[Any additional notes about:
- Known limitations
- Synthesis considerations
- Performance characteristics
- Compatibility notes]

---
*Documentation generated by HLSFactory OpenCode*
```

4. **Write the file** to `{{DESIGN_DIR}}/description.md`

## Guidelines

- Be accurate - only describe what the code actually does
- Be concise - avoid unnecessary verbosity
- Be helpful - include information useful for synthesis
- If uncertain about something, say "appears to" or "likely"
- Don't invent features that aren't in the code

## Output

- `{{DESIGN_DIR}}/description.md`
